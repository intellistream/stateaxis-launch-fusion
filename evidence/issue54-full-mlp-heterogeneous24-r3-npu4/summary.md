# Issue #54 full-MLP launch-fusion component closure

The r3 physical-B32 component campaign fixes the r2 SwiGLU launch failure, but
the frozen performance gate rejects the candidate because the bracket controls
are not stable enough. This is a documented matched negative result; it is not
an online, throughput, or vLLM-HUST speedup result.

## Root cause and fix

r2 stopped on the first control warmup with ACL runtime status `507035`. The
retained plog identifies `statecentric_qwen14b_swiglu_pto_stage` and reports
`VEC instruction error: the ub address out of bounds`. The kernel declared a
1024-element static `PtoVecTile` but placed adjacent UB regions using the
768-element dynamic chunk footprint. Those physical tile regions overlapped.

r3 makes the static capacity equal to the unchanged 768-element chunk and
derives every UB offset from the static footprint. Chunk ownership, 48 Vector
cores, GM addressing, arithmetic order, conversion modes, Gate ELF and
heterogeneous-24 Down ELF are unchanged. Two device-free official-image builds
were byte-identical; only the SwiGLU stage identity changed.

The frozen local source tree `9ec911648172d15553239c9db8eadf1f694976c1`
is also published verbatim as GitHub commit
`dd1205ded7d41f98b18aee5384a71ec5aea1c9dd`; the machine-readable mapping is
`benchmarks/issue54_full_mlp_heterogeneous24_source_publication_r3.json`.

## Frozen NPU result

Two fresh snapshots selected physical NPU4 from the probe-supported set
`{4,7}`: both cards had AICore=0 and sufficient HBM, and NPU4 had the greatest
free HBM. C0, candidate and C1 each ran five warmups and 50 measured samples in
fresh probe processes.

| Metric | Control 0 | Candidate | Control 1 |
|---|---:|---:|---:|
| Device event mean (µs) | 421.815 | 370.623 | 442.236 |
| Device event p50 (µs) | 420.350 | 370.180 | 439.970 |
| Device event p95 (µs) | 429.144 | 374.728 | 452.807 |
| Host total mean (µs) | 479.847 | 423.905 | 540.866 |
| Host total p50 (µs) | 475.487 | 420.157 | 502.088 |
| Host total p95 (µs) | 494.181 | 441.336 | 545.891 |
| Samples | 50 | 50 | 50 |

All three output files have SHA-256
`58dd6983e508a18f06b2cdabec05329adc32d49f2a3ebf66f21837d0fc3e589e`.
The independent BF16 oracle passes in every arm; its 9,344 bit mismatches are
signed-zero-only (`max_absolute=0`, `nonfinite=0`), as explicitly permitted by
the preregistration.

Against the bracket-control mean, the candidate's observed device-event mean is
14.213% lower and host total mean is 16.939% lower. However, C0/C1 device-event
means drift by 4.727%, exceeding the frozen 2% control-stability limit. The
component gate therefore fails even though the correctness, device-reduction
and host-regression sub-gates pass. The preregistration forbids retries and
online promotion after this failure, so the c1/8/16/32 × o32/128 serving matrix
was not run.

The lifecycle sampler observed NPU4 HBM from 3,418 to 3,889 MiB (471 MiB
increment). This is a lifecycle-level observed peak, not an arm-separated HBM
claim. The experiment container was removed and NPU4 had no process afterward.
